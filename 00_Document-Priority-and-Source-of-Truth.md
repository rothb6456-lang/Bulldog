\# Prototype Scope and UX Goals  
<br/>Version: v1.0  
Last Updated: 2026-08-18  
Status: Active  
Document Type: Prototype Scope  
Priority: Highest  
<br/>\## Purpose  
<br/>This document defines exactly what the current Bulldog Statbook prototype is intended to accomplish.  
<br/>The current prototype is a \*\*static front-end UX shell\*\* for desktop-first evaluation.  
<br/>It is not yet the Laravel application.  
<br/>\---  
<br/>\## Prototype Goal  
<br/>The immediate goal is to produce a visually credible multi-page prototype that allows review of:  
<br/>\- navigation  
\- information hierarchy  
\- layout density  
\- key workflows  
\- product tone  
\- visual alignment with bulldogstats.com  
<br/>\---  
<br/>\## What the Prototype Must Demonstrate  
<br/>The prototype must make it possible to evaluate:  
<br/>1\. login / entry experience  
2\. dashboard hierarchy  
3\. team list experience  
4\. team detail as the main working surface  
5\. roster presentation  
6\. role assignment presentation  
7\. player identity presentation  
8\. guardian relationship presentation  
<br/>\---  
<br/>\## Primary Review Question  
<br/>Does Bulldog Statbook feel like a serious, structured, coach/admin-oriented product that belongs to the Bulldog brand?  
<br/>\---  
<br/>\## In-Scope Pages  
<br/>The static prototype should include:  
<br/>1\. \`index.html\`  
2\. \`dashboard.html\`  
3\. \`teams.html\`  
4\. \`team-detail.html\`  
5\. \`create-team.html\`  
6\. \`player-identity.html\`  
7\. \`guardian-relationships.html\`  
<br/>\---  
<br/>\## In-Scope UI Elements  
<br/>The prototype should include:  
<br/>\- branded sidebar or app shell  
\- page headers  
\- cards  
\- tables  
\- badges  
\- forms  
\- tabbed sections on team-detail  
\- realistic placeholder data  
\- responsive behavior sufficient for desktop/tablet preview  
<br/>\---  
<br/>\## Most Important Screen  
<br/>The most important page in the prototype is:  
<br/>\# \`team-detail.html\`  
<br/>This page should feel like the operational center of the app.  
<br/>It should clearly show:  
\- team context  
\- roster management surface  
\- role management surface  
\- hierarchy between overview / roster / roles  
<br/>\---  
<br/>\## Out of Scope  
<br/>The prototype does not need to implement:  
<br/>\- real authentication  
\- backend API integration  
\- Laravel routing  
\- database operations  
\- game scoring  
\- game stats entry  
\- messaging  
\- social features  
\- notifications  
\- reporting dashboards beyond placeholders  
\- advanced mobile/PWA behavior  
<br/>\---  
<br/>\## Product Tone Goals  
<br/>The prototype should feel:  
<br/>\- serious  
\- modern  
\- premium but restrained  
\- analytical  
\- structured  
\- coach/admin focused  
\- sports-specific without being gimmicky  
<br/>It should not feel:  
<br/>\- generic  
\- noisy  
\- childish  
\- retro  
\- like a marketing landing page  
\- like a fan site  
<br/>\---  
<br/>\## Success Criteria  
<br/>The prototype is successful if it allows stakeholders to confidently react to:  
<br/>\- layout structure  
\- navigation clarity  
\- information density  
\- role/roster visual hierarchy  
\- overall desktop usability  
\- brand fit  
<br/>\---  
<br/>\## Deliverable Type  
<br/>The prototype should be:  
<br/>\- static  
\- HTML/CSS/minimal JS  
\- easy to host on Cloudflare Pages  
\- easy to revise quickly
